# Aureon — Project Handoff (Updated)

## Executive Summary

Aureon is a local-first Investment Operating System designed for a single user.

Deployment Model:

* Runs only on a local machine.
* Docker Compose based.
* No SaaS requirements.
* No multi-tenancy.
* No cloud infrastructure requirements.
* No enterprise-scale requirements.

Primary Goal:

Allow a user to manage their entire financial life from one application:

* Stocks
* Mutual Funds
* ETFs
* Crypto
* EPF
* PPF
* NPS
* Real Estate
* Cash
* Manual Assets

The project has transitioned from architecture work into release-candidate validation.

# Architectural Decisions

## Local-First Philosophy

The most important decision:

Aureon is LOCAL SOFTWARE.

Not SaaS.

Ignore recommendations involving:

* Kubernetes
* ECS
* Multi-region
* Auto-scaling
* Service Mesh
* Distributed Tracing
* Blue/Green Deployments
* Canary Releases
* Enterprise Observability
* Database Clustering

These are explicitly out of scope.

---

## Pipeline Strategy

Current:

```text
Single Orchestrated Execution Path
```

Reason:

* Single user
* Local machine
* Small asset universe

Do NOT introduce:

* Celery Chains
* Celery Chords
* Complex orchestration

Future Migration Trigger:

```text
>1000 assets
OR
Intraday refresh requirements
OR
Pipeline runtime >5 min
```

Only then consider Chain/Chord orchestration.
