# Aureon v1.0 — Context Transfer / Project Handoff

## Project Overview

Aureon is a local-first Investment Operating System designed for a single user.

Deployment Model:

* Runs exclusively on the user's local machine.
* Docker Compose based.
* Not intended for SaaS deployment.
* No multi-tenancy.
* No cloud infrastructure requirements.
* No enterprise-scale requirements.

Primary Goal:
Provide a complete personal portfolio management platform covering:

* Stocks
* Mutual Funds
* ETFs
* Crypto
* EPF
* PPF
* NPS
* Other manually tracked assets

Core Stack:

* FastAPI
* PostgreSQL
* Redis
* Celery
* RabbitMQ
* React + Vite

# Architectural Decisions Already Made

## Approved Architecture Fixes

The following issues were identified, verified through code evidence, and approved:

### Database Optimization

Implemented:

* positions(user_id) index
* transactions(user_id) index

Purpose:

* Eliminate sequential scans
* Improve dashboard and portfolio queries

Status:
Approved and implemented.

---

### Transaction Optimization

Problem:
Multiple database commits occurred inside price refresh loops.

Solution:

* Fetch prices first.
* Store results in memory.
* Execute a single batch transaction.
* Commit once.

Status:
Approved and implemented.

---

### HTTP Timeout Protection

Problem:
External API calls had no timeout protection.

Solution:

* Explicit request timeouts added.

Status:
Approved and implemented.

---

### Redis Recovery

Problem:
Redis failure during startup permanently disabled caching.

Solution:

* Lazy Redis initialization.
* Self-healing reconnection logic.

Status:
Approved and implemented.

---

# Pipeline Decision

Original Problem:
Pipeline tasks were dispatched concurrently:

1. Refresh Prices
2. Enrich Technicals
3. Generate Signals
4. Fetch News
5. Sentiment Analysis
6. AI Briefing

This created race conditions.

Decision:

For current scale:

* Single user
* Local machine
* Small asset universe

Use:

Single orchestrated execution path.

Do NOT introduce:

* Celery Chords
* Celery Chains
* Complex orchestration

Future migration trigger:

IF:

* Asset count > 1000
  OR
* Intraday refresh requirements emerge
  OR
* Pipeline execution exceeds 5 minutes

THEN migrate to:

Chain
→ Chord
→ Parallel Technical Enrichment

Current recommendation:
Keep it simple.
